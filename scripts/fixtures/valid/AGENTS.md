# AGENTS.md - 語音情緒辨識（SER）LLM Wiki 維護規範

本文件規範 Agent 在維護「語音情緒辨識（Speech Emotion Recognition, SER）LLM Wiki」時的核心行為準則、工作流程與品質門禁。

---

## 1. 核心定位、讀者設定與邊界

1. **唯一事實來源（Ground Truth）**：
   - 本 Wiki 的所有知識 100% 僅能來自 `raw/` 資料夾內的論文。
   - 嚴禁調用 AI 外部背景知識補充論文未提及的內容。
   - 論文未提及者寫「論文未提及」，未提供定義者寫「論文未定義」，無自研實驗或方法者寫「不適用（附理由）」。
2. **`raw/` 絕對唯讀原則**：
   - AI 完全不得移動、修改、刪除或重命名 `raw/` 內的任何檔案。
3. **讀者設定**：
   - **Wiki 讀者**：使用者本人（精準學術核對）與簡報階段的 AI。**Wiki 是下游簡報階段的唯一知識來源**。
   - **簡報讀者**：非該領域的新手學習者，採「教學／觀念導覽」順序。
4. **獨立審查界線**：
   - 獨立 AI 審查由使用者另開新對話進行，維護 wiki 的 agent 不審查自己的成果。

---

## 2. 停止與不確定處理準則

1. **強制停止條件**：
   遇到以下任一情況，AI **一律立即停下並回報使用者，不可自行推測或硬填**：
   - PDF 讀不到或出現亂碼
   - 頁碼對不上或引用出處存疑
   - 資料不足以填寫必填欄位
   - 規則互相衝突
   - 不確定內容是否確切來自論文
2. **腳本修復上限**：
   - 執行自動化檢查腳本若回報失敗，AI 最多自動嘗試修正 3 輪。
   - 若 3 輪修正後仍失敗，必須立即停下，條列失敗項目與原因，等待使用者裁決。

## 3. 語言、文字與全域引用規範

1. **語言風格與專有名詞**：
   - 內文以繁體中文撰寫。模型、資料集、特徵與指標名稱保留英文原名。
   - 專有名詞第一次出現時必須標註「中文（英文）」（例如：`未加權平均召回率（UAR）`），之後全文統一採用該中文譯名。
   - 數字、資料集名稱、模型名稱一律保留原文，不得翻譯。
2. **引用與頁碼格式（全 Wiki 一致）**：
   - 頁碼格式嚴格限定為四種之一：`(p. N)`、`(p. N, Table M)`、`(p. N, Fig. M)` 或 `(pp. N–M)`。
   - 原文引述一律保留英文原句：`> "英文原句" (p. N)`。
   - 非論文頁（實體頁、綜合頁、證據卡）引註時，頁碼前必須加來源連結：`[[slug]] (p. N)`，引文格式為 `> "英文原句" [[slug]] (p. N)`。嚴禁使用 `([[slug]] p. N)` 語法。
3. **數據與觀點歸屬標籤**：
   - 數字標註：數字後面必須緊接 `[本文]` 或 `[引述]` 再接頁碼。例如：`UAR X.X% [本文] (p. N, Table M)`、`N 位兒童 [本文] (p. N)`、非論文頁如 `UAR X.X% [本文] [[slug]] (p. N, Table M)`。
   - 同一句或同一表格儲存格內的**每個數字**（百分比、小數、樣本數、時數、類別數等）都要在同一句或同一格附有頁碼。
   - **不需頁碼的例外清單**（明列如下 8 項，腳本與 AI 不得自行增加例外）：
     1. 引用頁碼本身（如 `(p. N)` 中的數值）
     2. frontmatter 內的數值（如 `year: YYYY`）
     3. 檔名與連結（如 `[[slug]]`）
     4. 章節編號（如 `3.1`、`第 1 節`）
     5. 引用內的 Table／Fig 編號（如 `Table M`、`Fig. M`）
     6. 模型／資料集／指標名稱裡的數字（如 F0、X2Y 等代號或佔位符）
     7. 清單編號與標題編號（如 `1.`、`2.`、`## 1.`）
     8. 「基本資訊」區塊
   - 「核心貢獻與作者觀點」區塊：每個條列開頭必須嚴格標記 `[作者聲稱]` 或 `[AI 整理，待核對]`。

## 5. 實體分類與建頁門檻

1. **實體 6 大類別（Frontmatter `type:`）**：
   - `topic`：研究主題／挑戰標籤（如兒童 SER、跨語言泛化、多模態融合）。
   - `taxonomy`：情緒分類體系（如離散情緒、維度情緒）。
   - `dataset`：資料集。
   - `feature`：聲學特徵與前處理。
   - `model`：模型架構。
   - `metric`：評測指標。
   *註：訪談討論提及之名稱純屬範例佔位符，無預先核准，論文有提及且達門檻方可建頁。*
2. **建頁門檻與操作規則**：
   - 論文頁的「提及實體清單」中，**尚未建頁的實體一律使用純文字、不加 `[[ ]]`**。
   - 每次 Ingest 完成後，重新統計各論文頁提到的實體：**任何達到 2 篇或為核心貢獻者（`len(sources) >= 2` 或 `core_contribution_of`）即建立實體頁**。
   - 實體建頁後，**回頭把先前各論文頁「提及實體清單」中的該實體改成 `[[連結]]`**。
   - 實體頁 frontmatter 必須具備 `sources: []` 清單。
   - 實體頁內容**仍須引用 PDF 頁碼（如 `[[slug]] (p. N)`）**，不可只引用其他論文頁而缺原論文 PDF 頁碼。未達門檻者僅保留於論文頁內文，不單獨建頁。
3. **實體頁必備區塊**：
   - `## 定義`：包含英文原話引述（附頁碼 `> "英文原句" [[slug]] (p. N)`）與「中文說明（AI 整理，待核對）：...」。若論文未定義，寫「論文未定義」。
   - `## 核心屬性與特點`：每項皆須標註來源與 PDF 頁碼。
   - `## 在各論文中的應用與實驗表現`：每一句或表格格子皆標來源與 PDF 頁碼。
   - `## 矛盾／待釐清`：必備標題。若無衝突寫「無」。

## 6. 單篇論文筆記規範與必填／選填表

1. **一句話摘要**：
   - 以 frontmatter 的 `one_sentence_summary` 為唯一來源。論文頁正文不設同名章節，`index.md` 直接引用此欄位。
2. **必填／選填定義**：
   - 「不適用」＝該類型論文結構上沒有這項內容，需附理由（例如「不適用（綜述無自研實驗）」）。
   - 「論文未提及」＝這項內容本來該有，但論文沒寫。
   - 必填區塊不可空白。

| 區塊 | 方法 | 資料集 | 綜述 | 基準評測 |
| :--- | :--- | :--- | :--- | :--- |
| **摘要（frontmatter）** | 必填 | 必填 | 必填 | 必填 |
| **基本資訊** | 必填 | 必填 | 必填 | 必填 |
| **研究動機與欲解決問題** | 必填 | 必填 | 必填 | 必填 |
| **核心貢獻與作者觀點** | 必填 | 必填 | 必填 | 必填 |
| **提及實體清單** | 必填 | 必填 | 必填 | 必填 |
| **矛盾／待釐清** | 必填 | 必填 | 必填 | 必填 |
| **方法與架構** | 必填 | 必填（寫資料蒐集與標註流程） | 不適用 | 選填（寫評測設計） |
| **實驗設定** | 必填 | 選填（有基準實驗才填） | 不適用 | 必填 |
| **核心數據與成果** | 必填 | 必填（資料集統計，有基準結果一併列） | 選填（只記綜述強調的數字，全標 [引述]） | 必填 |
| **論文提及之局限性** | 必填（可寫論文未提及） | 必填（可寫論文未提及） | 必填（可寫論文未提及） | 必填（可寫論文未提及） |

## 7. Ingest 工作流程與步驟

1. **Ingest 順序（先專篇、綜述放最後）**：
   - 第 1 篇：`2008-fau-aibo.pdf`（資料庫類）
   - 第 2 篇：`2021-pepino-wav2vec2-ser.pdf`（方法類）
   - 第 3 篇：`2016-emoreact.pdf`（資料集＋基準）
   - 第 4 篇：`2024-ser-evals.pdf`（基準評測）
   - 第 5 篇：`2026-review-ser-adults-children.pdf`（綜述，檢驗綜述二手引述）
   - 一律**一次處理一篇**，嚴禁批次 Ingest。
2. **每篇 Ingest 8 個固定步驟**：
   1. **讀取確認**：讀取 PDF 並確認文字可完整讀取無亂碼。
   2. **擬定摘要與候選清單**：列出擬建或更新的論文頁、實體頁與數據摘要（**前 2 篇必須等使用者確認後才寫檔**；後 3 篇採自主建檔）。
   3. **撰寫論文頁**：依 `templates/paper-template.md` 與必填選填表建立 `wiki/papers/<slug>.md`。
   4. **建立或更新實體頁**：建立或更新符合門檻之實體頁，遵守 `templates/entity-template.md`。
   5. **更新全域索引**：更新 `wiki/index.md`。
   6. **追加操作日誌**：在 `wiki/log.md` 追加一筆紀錄。
   7. **執行自動化腳本**：執行 `scripts/check.py` 與 `scripts/check_numbers.py`。
   8. **完整回報**：條列新增與修改檔案清單、貼出腳本完整輸出、提供 `git diff` 摘要。**嚴禁僅回覆「完成」**。
3. **更新舊頁面規範**：
   - 後續論文與先前頁面有衝突或補充時，允許修改舊論文頁或實體頁，但**僅限改動「矛盾／待釐清」、「在各論文中的應用與實驗表現」或「提及實體清單」（實體建頁後回補雙向連結）**區塊。
   - 必須同步在 `wiki/log.md` 追加 `update` 記錄，寫明修改頁面與原因。

## 8. 索引（index.md）與日誌（log.md）規範

1. **`wiki/index.md` 格式**：
   - Papers 每項格式：`- [[slug]]｜類型｜一句話摘要`（一句話摘要直接引用 frontmatter 的 `one_sentence_summary`）。
   - Entities 按 `type` 分組，每項格式：`- [[slug]]｜名稱`。
   - 每次 Ingest 或建立綜合頁後皆必須同步更新。
2. **`wiki/log.md` 格式**：
   - 採 Append-only（僅向下追加），每一筆格式統一為：
     `## [YYYY-MM-DD] <類型> | <說明>`
   - `<類型>` 嚴格限定為：`init`、`ingest`、`update`、`synthesis`、`lint`、`deck`。
   - 標題下方必須逐行條列本次新增或修改之檔案路徑。

## 9. 跨論文綜合頁面（`wiki/synthesis/`）

1. **生成時機**：必須等 **5 篇論文全數 Ingest 完成**後才一次性建立。
2. **5 大主題**：
   - `datasets-comparison.md`（資料集全景對照）
   - `benchmark-matrix.md`（評測與基準矩陣）
   - `adult-vs-child-ser.md`（成人 vs. 兒童 SER 對比）
   - `architecture-evolution.md`（技術架構演進脈絡）
   - `open-challenges.md`（核心挑戰與開放問題）
3. **引用與標籤規範**：
   - 表格中每一格、內文中每一句比較陳述，皆須標明來源論文與 PDF 頁碼（如 `[[slug]] (p. N)`）。
   - 實驗設定不同時，必須明示「**設定不同，不可直接比較**」並具體說明差異。
   - 5 篇論文未覆蓋之環節標註「**論文未涵蓋**」，嚴禁補寫外部歷史。

## 10. 論文衝突與矛盾處理原則

1. **禁止 AI 自行選邊**：若論文間論點或實驗數據矛盾，必須並列雙方說法、出處與頁碼。
2. **區分衝突性質**：
   - 「**設定不同導致不可比較**」（如不同資料切分、不同情緒類別數）。
   - 「**真正衝突**」（相同設定下結論相反，或二手綜述引述錯誤）。
3. 統一收錄於各頁面之 `## 矛盾／待釐清` 區塊，供 Lint 標示與人工審查。

## 11. 自動化檢查與品質門禁（`scripts/`）

1. **唯讀與結束碼原則**：檢查腳本一律唯讀，不可擅改檔案；任何項目失敗結束碼必須非 0。
2. **腳本職責劃分**：
   - `check.py`：
     - 檢查失效雙向連結與孤兒實體頁。
     - 檢查實體與論文清單雙向一致性：每個實體頁 `sources` 裡的每篇論文，其「提及實體清單」皆必須有指向該實體的 `[[連結]]`；反之，論文頁清單裡的每個 `[[連結]]`，該實體頁的 `sources` 也必須包含該篇論文（機械化抓出建頁後漏補連結）。
     - 檢查 frontmatter `type:` 與必填欄位空白（依第 6 節表格）。
     - 檢查每篇論文頁與實體頁是否包含 `## 矛盾／待釐清` 標題（無衝突需寫「無」）。
     - 檢查 PDF 與論文筆記 1:1 對齊。
     - 檢查實體 `sources` 門檻（`len(sources) >= 2` 或核心貢獻）。
     - 檢查 `wiki/` 內所有頁面皆登記在 `index.md`。
     - 檢查 `log.md` 格式正確、日期合法（YYYY-MM-DD、不晚於當天且依序遞增）、僅有行新增。
     - 檢查「核心貢獻與作者觀點」每個條列開頭必須是 `[作者聲稱]` 或 `[AI 整理，待核對]`。
     - 檢查 `AGENTS.md` 字元數不得超過 12,000 字元。
   - `check_numbers.py`：
     - **檢查範圍**：只掃描 `wiki/papers/`、`wiki/entities/`、`wiki/synthesis/`，不掃描 `AGENTS.md`、`templates/`、`wiki/index.md`、`wiki/log.md`。
     - 抽取 Markdown 中的數字與頁碼，比對對應 PDF 頁面文字是否存在。
     - 檢查數字後必須緊接 `[本文]` 或 `[引述]`（缺標籤算失敗）。
     - **引述例外**：引述區塊（`>` 開頭之行）內的數字不要求 `[本文]` 或 `[引述]` 標籤，改由「引文是否逐字出現在該頁」來驗證。
     - 頁碼格式必須嚴格符合四種指定格式之一：`(p. N)`、`(p. N, Table M)`、`(p. N, Fig. M)`、`(pp. N–M)`。
     - **沒附頁碼的數字一律算失敗**（第 3 節例外除外）。
     - 找不到或無法判斷之項目必須於報告中列出，不可默默略過。
     - 表格抽字格式差異造成的潛在誤報需在報告中明確標示。
     - 檢查標註頁碼不超過該 PDF 總頁數。
3. **變異測試規範（Mutation Testing）**：
   - 故意放錯測試**必須在臨時副本（如 `temp/`）上執行**，驗證腳本能否抓出錯誤，嚴禁污染正式 Wiki。
4. **Commit 門禁**：提交前必須執行腳本，確認全數通過才可 Commit。

## 12. 下游簡報產出（`deck/`）與兩層溯源體系

1. **簡報規格**：
   - 單一檔案 HTML（內嵌 CSS/JS、鍵盤左右鍵翻頁），8–15 頁（目標 10–12 頁，無溢出）。
   - 教學順序：什麼是 SER → 情緒怎麼定義 → 資料集 → 特徵 → 模型 → 怎麼評估 → 兒童挑戰。
2. **兩層溯源與退回機制**：
   - **簡報階段只讀取 `wiki/`**，不得直接讀取 `raw/`。
   - 投影片頁尾標註對應之 Wiki 頁面與原論文頁碼。
   - 簡報若發現數字或內容錯誤，**必須退回「Wiki 對 PDF」那一層修正**，不可在簡報單獨打補丁。
   - 證據卡純度：一張證據卡只能引用一個 Wiki 頁面。

## 13. 版本控制規範（Git Rules）

1. **每篇 Ingest 獨立 Commit**：每篇論文 Ingest 完成且腳本全過後 commit 一次。
2. **提交前郵件核對**：提供 commit 指令前，**必須先請使用者確認 `git config user.email` 為 GitHub noreply 信箱**。
3. **英文 Conventional Commits**：統一使用英文 Conventional Commits（如 `feat(ingest): add 2008-fau-aibo paper and entities`）。
4. **嚴格禁止自動操作**：AI 絕不自動執行 `git commit` 或 `git push`；僅提供建議指令與訊息由使用者執行。
5. **禁止 `git add .`**：必須精確指定檔案或資料夾路徑。
6. **排除二進位檔案**：`raw/*.pdf` 必須排入 `.gitignore`（使用者決策）。
